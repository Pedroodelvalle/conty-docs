Toda chamada à API leva uma chave de API no cabeçalho `Authorization`, no esquema Bearer. A chave já identifica a sua marca; não há cabeçalho extra.

## Formato da chave

```text
ck_live_Y29udHkuN2YzYzE5ZDQ4YjJhNGU5ZjgxYzBkZTZhOWI1ZTM0MmY
```

A chave começa com `ck_live_`. Trate a chave inteira como uma senha.

## Usando a chave

<CodeGroup>

```bash cURL
curl https://api.appconty.com/public/v1/me \
  -H "Authorization: Bearer $CONTY_API_KEY"
```

```javascript Node.js
const response = await fetch("https://api.appconty.com/public/v1/me", {
  headers: { Authorization: `Bearer ${process.env.CONTY_API_KEY}` },
});

if (!response.ok) {
  const { error } = await response.json();
  throw new Error(`${error.code}: ${error.message} (${error.request_id})`);
}

console.log(await response.json());
```

```python Python
import os

import requests

response = requests.get(
    "https://api.appconty.com/public/v1/me",
    headers={"Authorization": f"Bearer {os.environ['CONTY_API_KEY']}"},
    timeout=10,
)
response.raise_for_status()
print(response.json())
```

</CodeGroup>

Chave ausente, malformada, revogada ou desconhecida responde sempre igual:

```json 401
{
  "error": {
    "code": "invalid_api_key",
    "message": "Chave de API ausente, inválida ou revogada.",
    "request_id": "req_01JC8Z3K9W2Q4R6T8V0X2Z4B6D"
  }
}
```

## Disponibilidade

A API pública, os webhooks e os cupons são liberados por marca pela Conty. Fale com o seu contato na Conty para ligar o que a sua integração precisa. Enquanto um recurso não está liberado, a chave continua válida e a API responde assim:

| O que não está liberado | Resposta |
|---|---|
| API pública e webhooks | `403 open_api_disabled` em toda rota de `/public/v1` |
| Cupons | `403 coupons_disabled` nas rotas `/coupons` |
| Comissão do cupom | O cupom e as vendas funcionam, com `commission_rate_bps` e `commission_cents` em `null`. Cupom só de rastreio segue com taxa `0` |

```json 403
{
  "error": {
    "code": "open_api_disabled",
    "message": "A API pública não está liberada para esta conta.",
    "request_id": "req_01JC8Z3K9W2Q4R6T8V0X2Z4B6D"
  }
}
```

Nos tenants com planos, a marca sem plano ativo recebe `403 plan_required`. A chave não é revogada e volta a funcionar quando a marca assina.

## Escopos da chave

<Note>
  **Beta, ainda não publicado em produção.** Os escopos chegam junto com a [escrita de campanhas](/api/referencia/campanhas-escrita) e ainda não valem em `https://api.appconty.com`.
</Note>

Ler não precisa de escopo: toda chave lê o que a marca vê no painel. Escrever precisa. Cada chave tem uma lista de escopos de escrita, escolhida na criação. A lista não muda depois: para trocar escopo, crie outra chave e revogue a antiga.

| Escopo | O que libera |
|---|---|
| `campaigns:write` | Criar rascunho de acordo, editar, pausar, encerrar, arquivar e excluir, subir e anexar arquivo, montar os cupons da campanha, e [operar o quadro](/api/referencia/quadro): candidaturas, entregas, prazos, briefing e remoção |
| `campaigns:spend` | As ações que movem dinheiro da marca: publicar, renovar, editar acordo em `review`, mudar verba, pagamento ou direito de uso de acordo publicado, subir o cachê do creator e depositar a verba de comissão dos cupons. Vale junto com `campaigns:write` |
| `chat:write` | [Enviar mensagem ao creator](/api/referencia/mensagens) |

`communities:write` e `ads:write` estão reservados: em breve, ainda sem rotas.

Uma chave sem escopos é só de leitura. `GET /me` devolve os escopos da chave em `api_key.scopes`:

```json
{
  "enterprise": { "id": "5e4d3c2b-1a0f-4e9d-8c7b-6a5f4e3d2c1b", "name": "Marca Exemplo" },
  "api_key": {
    "id": "7e6d5c4b-3a2f-4e1d-9c0b-8a7f6e5d4c3b",
    "name": "Agente de campanhas",
    "hint": "a9Xk",
    "scopes": ["campaigns:write", "chat:write"]
  },
  "campaign_model": "agreement"
}
```

### Por que publicar tem um escopo à parte

`campaigns:write` sozinho deixa a integração montar e ajustar a campanha sem comprometer saldo. Só a chave com `campaigns:spend` consegue:

- publicar: `POST /campaigns` com `status: "review"` ou sem `status`, `PATCH /campaigns/{id}` com `status: "review"` e `POST /campaigns/{id}/status` com `status: "review"`;
- renovar: `POST /campaigns/{id}/renew`;
- editar acordo em `review`: ele está esperando saldo, e salvar a edição tenta pôr no ar e reservar a verba;
- mexer no dinheiro de acordo publicado: `PATCH /campaigns/{id}` fora do rascunho que muda `budget_cents`, `usage_rights_duration`, `payment_type` ou `coupon_commission_budget_cents`, porque subir a verba compromete saldo da marca;
- subir o cachê do creator: `PATCH .../applications/{application_id}/proposed-amount` e `PATCH .../creators/{creator_id}/scope-amount`;
- depositar a verba de comissão dos cupons: `POST /campaigns/{id}/coupon-commission/budget`.

Dê `campaigns:spend` só para a integração que pode gastar a verba da marca.

### Quando falta o escopo

A API responde `403 insufficient_scope`, com o escopo que falta em `details[0].required_scope`. Nada é gravado e nenhum saldo é reservado.

```json 403
{
  "error": {
    "code": "insufficient_scope",
    "message": "Publicar campanha reserva saldo da marca e exige o escopo campaigns:spend.",
    "details": [
      {
        "message": "A chave precisa do escopo campaigns:spend.",
        "required_scope": "campaigns:spend"
      }
    ],
    "request_id": "req_01JC8Z3K9W2Q4R6T8V0X2Z4B6D"
  }
}
```

Numa rota de escrita, a API confere nesta ordem:

1. O recurso está liberado para a marca? Senão, `403` com o código da área, como `chat_disabled`.
2. A chave tem o escopo? Senão, `403 insufficient_scope`.
3. O cargo do dono da marca tem a permissão que o painel exige para a ação? Senão, `403 forbidden`.

<Note>
  **Chaves que já existiam** receberam `chat:write`, para continuar enviando mensagem como antes. Elas não têm `campaigns:write` nem `campaigns:spend`: para escrever em campanha, crie uma chave nova com esses escopos. `/coupons` e `/conversion-events` não usam escopo e seguem liberados só pela [disponibilidade](#disponibilidade) de cupons. Os cupons de campanha (`/campaigns/{id}/coupon-pool`, `/coupons/bulk` e `/coupon-commission/budget`) usam `campaigns:write`.
</Note>

## Criar uma chave

1. No painel, abra **Plugins → Integrações**.
2. Clique em **Nova chave**, dê um nome e escolha os [escopos](#escopos-da-chave) de escrita que a integração precisa.
3. Copie a chave na hora.

<Warning>
  **A chave aparece uma vez só.** A Conty guarda apenas um hash dela e não consegue mostrar de novo. Se perder, revogue e crie outra.
</Warning>

Para gerenciar chaves, o seu cargo precisa da permissão **Gerenciar chaves de API e webhooks**. Cada marca pode ter até 10 chaves ativas.

## Revogar uma chave

Em **Plugins → Integrações**, clique em **Revogar** na chave. A revogação vale na hora: a próxima chamada com ela já recebe `401 invalid_api_key`.

A lista mostra quando cada chave foi usada pela última vez. Use isso para achar chave esquecida antes de revogar.

## Boas práticas

- **Nunca use a chave no front-end**, em app mobile ou em qualquer código que roda no aparelho do usuário. A chave dá acesso à API inteira da sua marca. Chame a Conty só a partir do seu servidor.
- Guarde a chave num gerenciador de segredos ou em variável de ambiente, nunca no repositório.
- Crie uma chave por integração. Assim você revoga uma sem derrubar as outras.
- Para trocar uma chave, crie a nova, publique no seu sistema e só então revogue a antiga.
- Suspeita de vazamento? Revogue na hora e crie outra.
