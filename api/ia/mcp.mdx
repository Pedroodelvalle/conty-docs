A Conty publica um servidor MCP (Model Context Protocol) remoto. Qualquer cliente compatível com MCP remoto por HTTP passa a enxergar as tools da Conty e opera a conta da marca em nome da pessoa logada.

<Card title="Guia para marcas" icon="book-open" href="/marcas/mcp">
  Versão sem termos técnicos, para quem opera campanhas.
</Card>

## Servidor

| | |
|---|---|
| Endereço | `https://mcp.appconty.com/mcp` |
| Transporte | Streamable HTTP |
| Autenticação | OAuth, com o login da Conty |
| Quem conecta | Contas de marca com assinatura ativa. Contas de creator não conectam |

<Warning>
  **É preciso ter uma assinatura ativa da Conty.** Sem ela, o login não libera o acesso. Fale com o [time da Conty](/help-center/contact) para contratar.
</Warning>

## Autenticação

A autenticação é OAuth, feita pelo próprio cliente na primeira conexão:

<Steps>
  <Step title="O cliente abre o login da Conty">
    A pessoa entra com e-mail e senha e confirma o código enviado por e-mail.
  </Step>
  <Step title="A pessoa escolhe as permissões">
    **Leitura** (`campaigns:read`) vem sempre. **Escrita** (`campaigns:write`) é opcional: só com ela o agente cria campanhas, envia convites, decide candidaturas e revisa entregas.
  </Step>
  <Step title="O cliente guarda o token">
    O cliente renova o acesso sozinho. Para mudar as permissões, desconecte e conecte de novo.
  </Step>
</Steps>

O agente opera sempre a empresa do login. Não há "empresa atual" guardada na sessão nem troca de empresa pela conversa.

## Tools

O catálogo de tools vem da Conty no momento da conexão, então tools novas aparecem sem reinstalar. Elas se dividem assim:

| Área | Exemplos de tools | Escopo |
|---|---|---|
| Campanhas | `listar_campanhas`, `detalhar_campanha`, `contagens_campanha`, `criar_campanha`, `editar_campanha`, `mudar_status_campanha` | leitura e escrita |
| Creators | `buscar_creators`, `ver_perfil_creator`, `convidar_creators_campanha`, `remover_creator_campanha` | leitura e escrita |
| Candidaturas | `decidir_candidatura`, `cancelar_convite` | escrita |
| Missões e entregas | `listar_missoes`, `aprovar_video`, `pedir_alteracao_video`, `recusar_video`, `recuperar_video`, `revisar_asset_missao`, `reconvidar_creator` | leitura e escrita |
| Conversas | `abrir_conversa`, `enviar_mensagem` | escrita |
| Comunidades | `detalhar_comunidade`, `analytics_comunidade`, `compartilhar_campanha_comunidade` | leitura e escrita |

Sessão sem a permissão de escrita só recebe as tools de leitura: se uma tool de escrita "não existe" no cliente, quase sempre é isso.

## Limites e comportamento

- **Confirmação**: o agente pede confirmação antes de ações de escrita.
- **Erros crus**: a tool devolve o corpo de erro original da Conty. Um conflito de estado (por exemplo, pausar campanha com missões em andamento) é informação para o agente corrigir a chamada, não falha da tool.
- **Escopo da marca**: tudo o que o agente vê e faz está limitado à empresa do login e ao que o cargo da pessoa permite na Conty.
- **Dados sensíveis**: o MCP segue as mesmas regras de visibilidade do painel; o que a pessoa não vê no painel, o agente também não vê.
